# Cross-Pod Evidence Contract: Prep Manager (Pod 02)

**Upstream Stage:** Step 01 Receiving  
**Current Stage:** Step 02 Prep Compliance  
**Downstream Consumers:** Step 03 Pack Manager, Step 05 Recovery Manager (Disputed Prep Fee Claims)

---

## 1. Purpose & Interoperability

When an inbound shipment reaches Amazon fulfillment centers weeks after prep, Amazon often levies inbound defect fees (e.g. for alleged polybag seal failures, missing suffocation warnings, barcode readability issues, or label placements on seams). 

Without an immutable, machine-readable evidence record captured at the prep bench, prep center owners and sellers have no defensible proof to reverse these chargebacks.

This contract specifies the schema of the evidence record generated by the **Prep Manager Agent (Pod 02)**. Step 05 (Recovery Manager) reads this record along with Receiving (Pod 01) and Pack (Pod 03) records to assemble automated reimbursement claims against Amazon.

---

## 2. Shared Unit Identifier

All records across all five buildathon pods join on `unit_id` (`UNIT-0001` through `UNIT-0100`).

```text
  01 Receiving         02 Prep Compliance         03 Pack             05 Recovery
  [UNIT-0001]   ───▶   [UNIT-0001]         ───▶   [UNIT-0001]   ───▶  Reads all three
  Arrival photo        3-view evidence             Box seal proof      Builds claim
```

---

## 3. Schema Structure & Key Fields

The authoritative schema is defined in [`prep_evidence_contract.json`](prep_evidence_contract.json).

### Core Fields
- `record_id`: Prefixed with `PRP-` (e.g., `PRP-0001`).
- `unit_id`: Foreign key join string (`UNIT-0001`).
- `org_id`: Tenancy identifier (`org_demo_alpha` or `org_demo_bravo`).
- `overall_status`: Deterministic verdict: `PASS`, `FAIL`, or `UNCERTAIN`.
- `workflow_state`: `completed`, `pending_review`, or `overridden`.
- `issue_explanation`: Concise, human-readable sentence summarizing the condition.
- `failure_reasons`: List of itemized defect descriptions.
- `evidence_regions`: Pixel-level coordinates `[x, y, w, h]` and view identifier (`front`, `back`, `label`) linking the decision directly to photographic proof.
- `calibration`: Quality assessment (blur, glare, resolution) confirming image integrity.
- `performance`: Latency (ms) and compute cost ($), verifying compliance within prep economics ($0.40 - $1.10).

## 4. Individual Check Vocabularies

Every individual check produces a deterministic status:
1. `polybag_present_sealed`: `PASS`, `FAIL`, `UNCERTAIN`, `NOT_REQUIRED`
2. `suffocation_warning`: `PASS`, `FAIL`, `UNCERTAIN`, `NOT_REQUIRED`
3. `fnsku_label_placement`: `PASS`, `FAIL`, `UNCERTAIN`
4. `original_barcode_covered`: `PASS`, `FAIL`, `UNCERTAIN`
5. `expiry_date`: `PASS`, `FAIL`, `UNCERTAIN`, `NOT_REQUIRED`
6. `handling_marks`: `PASS`, `FAIL`, `UNCERTAIN`, `NOT_REQUIRED`
